# Pusat notifikasi

Lonceng membuka pengingat aktif, diurutkan dari yang paling mendesak. Judul **Notifikasi** tidak menampilkan angka; tab **Semua** menampilkan jumlah seluruh pengingat aktif dan tab **Belum dibaca** menampilkan jumlah pengingat yang belum dibaca dengan gaya angka yang sama. Panel mendukung tema terang/gelap, navigasi keyboard, scroll internal, dan maksimal lima item per halaman. Tinggi panel tetap saat daftar berisi maupun kosong: `min(48rem, 88dvh)` di desktop dan `94dvh` di HP. Area konten mengisi ruang di antara header dan footer sehingga footer tetap di bawah; daftar yang panjang digulir di dalam panel. Di HP panel muncul dari bawah. Membuka panel tidak otomatis menandai semuanya dibaca; klik item atau gunakan **Tandai semua dibaca**.

- Tagihan: belum lunas dan jatuh tempo maksimal tiga hari ke depan, hari ini, atau terlambat. Satu item per tagihan; perubahan tahap jatuh tempo menandainya belum dibaca lagi. Klik membuka formulir tagihan terkait, tanpa mengubah status atau saldo.
- Anggaran: pengeluaran bulan berjalan mencapai 80%, 100%, atau melebihi batas. Satu item per kategori. Naik tahap menjadi belum dibaca lagi. Klik membuka detail kategori bulan berjalan. Ambang notifikasi 80% terpisah dari indikator kartu anggaran yang sudah menggunakan 75%.
- Tabungan: mengikuti pengaturan pengingat dan tanggal target. Tidak muncul untuk target selesai/diarsipkan/dihapus atau jika sudah ada setoran bulan ini. Klik membuka detail target.
- Catatan: mengikuti jam di Pengaturan, hanya jika belum ada catatan hari ini. Klik membuka Tambah Catatan.

Pengingat dihitung dari data aplikasi yang tersedia, bukan riwayat notifikasi permanen. Kondisi yang selesai menghilang dari daftar aktif. Tanggal/jam diperbarui setiap 30 detik dan saat jendela aktif kembali. Jika sumber data gagal dimuat, panel menampilkan pesan dan tombol coba lagi, tanpa menyatakan semua pengingat sudah kosong.

Status baca disimpan per akun dalam tabel Supabase `notification_reads`, terpisah dari snapshot keuangan. Terapkan `supabase/migrations/20261123032704_create_notification_reads.sql` sebelum memakai sinkronisasi cloud. RLS membatasi `SELECT` dan `INSERT` pada `auth.uid()` pemilik; klien tidak diberi izin update/delete. Kunci gabungan akun dan identitas tahap pengingat membuat pengiriman ulang idempoten, tanpa mengubah waktu baca pertama yang diterima server. `read_at` membawa waktu penandaan dari perangkat; jam perangkat dapat berbeda.

Identitas tetap memakai `readKey`: tagihan mencakup ID, jatuh tempo, dan tahap segera/hari ini/terlambat; anggaran mencakup kategori, bulan, dan tahap; tabungan mencakup target/bulan; pengingat catatan mencakup tanggal. Membaca tahap hari ini tidak menandai tahap terlambat sebagai dibaca. Penanda tidak mengubah saldo, anggaran, tagihan, atau transaksi.

Penandaan langsung terlihat pada perangkat ini, lalu disimpan bersama antrean sinkronisasi di IndexedDB `dompet-santai-notification-reads-v1`. Antrean dipisahkan berdasarkan akun. Logout atau berpindah akun tidak menghapus antrean akun sebelumnya, tetapi hanya akun aktif yang boleh mengirimnya. Request akun sebelumnya dibatalkan dan respons terlambat tidak diterapkan ke akun baru. Pengiriman memakai penambahan per penanda, bukan mengganti daftar seluruh akun, sehingga pembacaan serentak dari perangkat lain tidak hilang.

Sinkronisasi berjalan saat aplikasi dibuka, panel notifikasi dibuka, koneksi kembali, tab/jendela aktif kembali, dan setiap 30 detik selama halaman terlihat. Tab browser yang sama juga menerima sinyal perubahan melalui BroadcastChannel/storage. Ini sinkronisasi berkala, bukan Supabase Realtime. Tombol **Coba lagi** memuat ulang status baca sekaligus sumber pengingat. Pembacaan cloud memakai pagination agar tidak berhenti pada batas respons pertama. Gangguan jaringan atau tabel yang belum tersedia ditampilkan sebagai peringatan; hasil gagal tidak dianggap sebagai daftar pengingat kosong.

Penanda lama dari `localStorage` `dompet-santai-notifications-v1:<user-id>` diimpor otomatis (maksimal 1.000 penanda sesuai format lama) ke antrean akun yang sama. Format lama tidak mencatat waktu baca, sehingga `read_at` menggunakan waktu impor; data lama tidak dihapus. Jika IndexedDB tidak tersedia, penanda yang belum tersinkron ditahan di memori selama sesi dan aplikasi menjelaskan keterbatasannya. Membersihkan data situs dapat menghapus antrean yang belum sampai cloud. Membuka ulang aplikasi sepenuhnya offline tetap mengikuti keterbatasan PWA yang ada.

Backup, restore, dan reset keuangan tidak menyertakan atau menghapus status baca ini. Pengingat aktif tetap dihitung dari data terkini; tabel ini bukan arsip isi notifikasi. Pengingat mencatat dapat dikirim melalui Web Push saat aplikasi ditutup setelah perangkat diaktifkan di Pengaturan dan server dikonfigurasi; lihat [Web Push](web-push.md). Sinkronisasi status baca tetap berjalan saat aplikasi aktif; tidak memakai Background Sync. Tagihan tetap memerlukan tabel pengingat yang sudah digunakan fitur Tagihan Mendatang.

Pengujian: `npm run test:sql:notifications` menjalankan migrasi dan pemeriksaan RLS dua akun pada PGlite lokal; `test/unit/notifications.test.ts` dan `test/unit/notification-read-storage.test.ts` memeriksa tahap dan aturan penggabungan. `test/e2e/notification-sync.spec.ts` memeriksa dua konteks browser, offline/reload/reconnect, data lama, akun berbeda, pengiriman serentak, respons hilang, kegagalan penyimpanan, dan pagination cloud. Skenario `notification` dalam `test/e2e/settings.spec.ts` tetap memeriksa panel, navigasi, tema, dan layar pendek. API pada pengujian browser ditirukan; hasilnya dibedakan dari penerapan/verifikasi pada Supabase nyata.

Server dev dan `.env` Supabase diperlukan; secret key hanya dibaca proses Node pengujian, tidak dikirim ke browser atau dicetak. Perubahan lewat SQL Editor tidak otomatis mendaftarkan file pada riwayat Supabase CLI.
